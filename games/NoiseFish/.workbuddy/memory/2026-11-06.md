- 关键技术点（都踩过坑）：
  - FishSegment 必须**缓存初始尺寸**（Awake 里 baseScale = target.localScale），
    Apply 乘在初始尺寸上而不是当前尺寸 → 否则 SetPresence 每帧调用会**累积缩小**
  - 整鱼尺寸改用 `FishActor.SetOverallScale()`，**不再改父物体 transform.localScale**
    （否则父级 scale 与段缩放叠加 → 鱼会缩水一半）

## 用户实机反馈：「只有一个3段的粉色鱼，其他的什么也看不到」

诊断出**三个真实缺陷**（都不是我预想的那些）：

1. **材质引用丢失 → 洋红色**
   prefab 里 `m_Materials: - {fileID: 0}` = null 材质 → Unity 渲染成洋红色（错误色）。
   根因：`new Material()` + `sharedMaterial` 的临时材质**不会被序列化进 prefab**。
   修法：材质必须存成工程资产（`AssetDatabase.CreateAsset` 到 `Assets/Materials/`）。
   ⚠️ **这是 Unity Editor 脚本的通用坑**：任何 `new Material()` 赋给 prefab 都会变洋红。

2. **球壳内壁全黑**
   默认 Directional Light 从上往下照，球壳内壁法线朝内 → 背光全黑。
   修法：删平行光，改球心点光源。
   ⚠️ **点光源辐照度 ∝ intensity/d²**：房间半径 14 时，intensity 2.2 只有 0.011 辐照度，
   根本看不见。要几百（用了 260）。
   → 以后凡是"大空间 + 点光源"，强度必须按 d² 算，不能拍脑袋。

3. **鱼立刻漂离轨道 → 0.5s 就消散**
   出生点在公转，鱼出生后原地漂移 → 判定位置与眼睛看到的位置不一致 → 看着它也算"没注视"。
   修法：`FishActor.followTarget`，鱼跟随出生点。

顺带加了 `SpawnMarker`（脉动光点）：轨道不可见时玩家不知道往哪看，注视机制无法触发。

## 教训

- **Editor 脚本生成资源必须用工程资产**：临时 Material/GameObject 赋给 prefab 会丢引用。
- **Unity batchmode 跑不通**：`HandleProjectAlreadyOpenInAnotherInstance` —— 工程正开着就进不去。
  所以场景生成还是得用户在编辑器里跑菜单（我加的 `BuildBatch()` 留着，等工程关着时可用）。
- **静态自检查不出"看不见"这类问题**：null 材质、灯光不足、背光面全黑 —— 都是渲染期现象。
  这类必须靠实机验证，cscheck.py 只能拦编译错。

## 第二轮实机反馈：「和刚才没区别」→ 真相是场景从未重建

我误判了方向，以为是渲染 bug，实际是**场景文件停在 21:59 旧版**（菜单没被重跑）。
教训：**代码生成资源的工程，必须先确认"场景文件时间戳 > 脚本时间戳"，否则一律按"没重建"处理。**

截图反推的信息（很有用）：
- 上半屏蓝渐变 = 天空盒；下半屏暗棕 = **旧方房间的地板**（不是球壳）
- → 球壳从内部完全不可见 = null 材质 → 默认单面材质 → 背面剔除
- → 那个洋红点 = 旧场景里唯一的鱼（null 材质）
- → "球壳是亮的" 是误读，其实是默认平行光照到的地板

**根治：场景自动重建**
`[InitializeOnLoadMethod]` + 代码指纹（MD5）+ 延迟一帧重建。
只有构建成功才写指纹，失败会重试。代码没变就不动场景（保留手动调整）。
→ 以后改完代码直接切回 Unity，场景自动跟上，不再需要"记得点菜单"。

## batchmode 实测要点
- Unity 编辑器**开着**时 batchmode 进不去：`HandleProjectAlreadyOpenInAnotherInstance`
- 需先 `taskkill` 掉 Unity.exe（PID 从 tasklist 查）
- 首次 batchmode 要重新导入工程，很慢（8 分钟+）
- `-executeMethod` 的方法里**不能有 EditorUtility.DisplayDialog**（batchmode 会卡住）→ 故加 BuildBatch() 入口
- 日志用 `-logFile <路径>` 指定，比 stdout 可靠
